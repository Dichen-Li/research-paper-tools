# 原生可编辑 PPT

将指定流程、框架、结构或机制图重建为原生形状、文字和连接关系。原图提供视觉方向，不另行设计汇报风格，不套用通用演示文稿主题。

## 构建

- 一张图默认一页，保持原始比例、分区、层级、阅读顺序和子图标号。多图按实际请求组织，不额外增加封面、原图参考页或说明页。
- 文字、节点、区域、连接线、箭头及可编辑公式使用原生对象。标准节点优先把文字和形状放在同一对象中，便于整体移动；特殊自由形状需单独标签时可组合。简单图直接创建对象即可；复杂图可集中记录节点 ID、边的起终点、方向、路径和标签。
- 关系从原图读取，不从节点距离或环形摆放推断。保留单双向、虚实线、交叉、包含关系和遮挡层次；边标签不误当节点。
- 直线优先使用绑定节点的原生连接器。复杂路径或工具只支持自由定位时，可保留原生线，但需说明端点不随节点自动移动；“可编辑”不等于“已绑定”。用户明确要求绑定时不降级代替。
- 原图不作为背景、局部裁片、图片拼贴、隐藏描图层或密集路径留在成品。定量图插图优先用原生图表或代码生成的可编辑路径重建，不把复杂图截成 PPT 内的位图。
- 近似曲线轮廓和部件外形可用原生自由形状；不把标签拆成逐字对象，不把一根箭头的箭头头和杆无必要地分离。折线路径可由有明确归属的少量原生线段组成。

## 工具与可靠的实现细节

用当前宿主可用的原生 PPT 工具；桌面有 `load_workspace_dependencies` 时先获取其运行时路径。按实际版本读取所需 API，不硬编码本机缓存，不要求加载整套展示设计资料。

在当前宿主允许的工具内选择 PptxGenJS、python-pptx 或 Artifact Tool；候选库清单不豁免宿主明确的作者工具、依赖发现和最终检查要求，已完成的宿主检查不重复执行。只选一个适合必需对象的工具，不为普通矩形、文字、直线反复探测；复杂公式或自由形状确有不确定能力时，做一个最小探测后复用。

- PptxGenJS 可复用 `assets/pptxgenjs-native-template.mjs`；可直接修改示例，或用 `--map figure.json` 读取数值定义（`source`、可选`slide`、`nodes`、`edges`、`fontFace`、`language`），用 `--output` 指定输出。默认按源比例创建画布，指定固定画布时等比居中；节点为一个对象，多段边为一个开放路径。模板校验端点与声明的节点边界是否对应，但不替代源图关系核对。
- 模板的边仍为自由几何，未绑定节点；需要移动节点后连线跟随时，选择当前宿主支持绑定的工具/API并验证导出绑定关系，不用模板的普通线冒充绑定。模板可接收富文本 runs；字体与语言依原图和已安装字体设置，不写死必须存在的中文字体。
- 源图坐标只做一次到幻灯片坐标的比例转换。不要把像素值直接当成英寸；PptxGenJS 使用英寸，某些宿主 API 使用96 dpi的CSS像素，按实际 API 核对。
- 箭头在 OOXML 中 `a:headEnd` 位于路径起点，`a:tailEnd` 位于终点。PptxGenJS 4.0.x 的 `beginArrowType`／`endArrowType` 对应这两端；单向关系的箭头在末段终点，双向关系还在首段起点。端点顺序不确定时验证一次导出结果。
- 普通标签保留原生文字；上下标用 baseline／富文本 runs，复杂分式、矩阵等优先使用真实 Office Math。字体缺失时选视觉接近且覆盖字符的字体，不因字体不完全相同停工。
- 若工具无法保留关键公式的内容和编辑性，尝试可行的原生路线；仍无法实现时说明具体缺项，不自行改公式，也不把截图称为可编辑公式。
- 先确定最终文本框大小、边距、字号和断行，不依赖打开文件后自动缩放来修复布局。

## 导出、对照与编辑性

实际运行构建程序，渲染导出的 PPTX，并按共用视觉核对流程对比原图。检查文字、公式、连接方向、遮挡、裁切和比例，不能只看对象数量。

若宿主没有现成渲染器但已安装 LibreOffice 和 Poppler，可使用同技能 `scripts/render_office.py`，同时支持 PPTX／XLSX：

```text
python <skill-dir>/scripts/render_office.py editable.pptx --output-dir <private-qa-dir> --round 1 --soffice <actual-executable> --pdftoppm <actual-executable>
```

`--round N` 可把每轮输出放入 `rN/`，已有结果不会静默覆盖。脚本采用隔离 profile，报告实际渲染器、版本和检查盲区；失败明确返回 `ready:false`，不会偷偷改用缩略预览。已有一次合适的真实渲染即可，不为追求多软件一致反复导出。

运行 `python <skill-dir>/scripts/check_native_office.py editable.pptx`。PASS 仅说明结构检查通过；WARN 指需要结合原图复核，例如疑似伪上下标、对象异常密集、被识别的原生公式兼容图片。公式兼容分支只在有真实公式内容、相同几何框且单图片关系可解析时被区别处理，仍需确认其仅对应公式；未知分支不自动放行。检查器不能验证公式与图片像素等价，也不替代语义核对。只有用户明确请求已有 PPT 的修改时才使用可导入并保留原对象的工具，PptxGenJS 重建不等于保留原文件。

默认只交付可编辑 `.pptx`。执行过的构建代码和渲染预览留私有目录；用户要求代码时才交付，并确保实际依赖、相对路径和运行说明齐全。
